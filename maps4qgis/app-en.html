Supported Map Data

            
    
              
  • GeoPDF exported from QGIS with Add georeferencing information enabled. Any GeoPDF containing compliant georeferencing data is also supported.
    • 
              
  • 4-corner GPTS registration required. Common 4-corner LPTS point orders are normalized automatically.
    • 
              
  • GPTS coordinates are interpreted as WGS84 lat/lng per GeoPDF specification.
    • 
              
  • For 3D display, the GeoTIFF DEM must cover the full GeoPDF extent. A DEM with a small margin outside the PDF extent is recommended.
    • 
              
  • The GeoPDF and DEM CRS must match. The DEM must include georeferencing metadata and an EPSG code.
    • 
              
  • The DEM must be a single-band GeoTIFF representing bare-earth elevation in meters. DSM, CHM, canopy-height data, hillshade images, and contour-line images are not treated as DEM.
    • 
              
  • Compressed GeoTIFF, BigTIFF, and multi-band DEM are not supported at this stage. Export an uncompressed single-band GeoTIFF from QGIS.
    • 
              
  • If NoData or missing cells are present inside the PDF extent, the 3D terrain may be incomplete or visually unnatural.
    • 
              
  • Alternatively, a DEM can be fetched automatically from GSI elevation tiles (online only). Each point uses DEM1A (1 m), DEM5A (5 m) or DEM10B (10 m), whichever is the finest available. Areas with no data in any of them are treated as sea (0 m) when they adjoin low ground; enclosed inland gaps are interpolated. Supported for maps in Japan: in the map's CRS for GeoPDFs in Japan Plane Rectangular CS or JGD2011 lat/lng, and in JGD2011 lat/lng for maps in other CRSs (such as Web Mercator). Only if GSI tiles cannot be fetched, alternatives are offered depending on the reason: retry, coarser GSI 10 m, AWS Terrarium (low accuracy, reference only), a GeoTIFF file, or 2D-only import. For maps outside Japan, the choices are AWS Terrarium, a GeoTIFF file, or 2D-only import; the AWS DEM is made in WGS 84 lat/lng. A GeoTIFF DEM in WGS 84 lat/lng can be used with a map in any coordinate system.
    • 
            

          

          

            
Device & Environment

            
    
              
  • Android Chrome recommended. iOS Safari: compliant by spec, untested.
    • 
              
  • HTTPS required — Geolocation API browser requirement.
    • 
              
  • GPS accuracy: ±3–15 m outdoors (open sky).
    • 
              
  • Compass accuracy: ±5–30° — subject to device quality and magnetic interference.
    • 
              
  • Backup exports use the selected save location when the browser supports it. Otherwise they use the browser's download settings. On Android, they often appear in Downloads or a similar folder.
    • 
            

          

          

            
Design Decisions

            
    
              
  • No tile maps. This app targets site-specific field maps, not general navigation. Tile maps require external servers with continuous connectivity, or the implementation involves trade-offs against lightweight operation. GeoPDF import enables fully offline operation with custom maps.
    • 
              
  • Affine correction for projection convergence. The image is placed using a 4-corner affine transform derived from GPTS coordinates. This corrects for meridian convergence (rotation) introduced by any local projected CRS (Japan Plane Rectangular, UTM zones, etc.). Perspective distortion from wide-area or high-latitude coverage is not corrected.
    • 
              
  • No server-side processing. All map conversion and storage runs in-browser. Field data never leaves the device. Automatic DEM fetching only requests GSI elevation tiles covering the map extent at import time.
    •
